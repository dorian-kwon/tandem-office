# AI 수정 되돌리기 기록 설정 설계

상태: 사용자 승인 완료 (2026-11-18). 처음 엑셀만 대상으로 삼았으나 후속 승인으로 아홉 편집기 전체에 적용한다.

## 목적과 공용 계약

큰 AI 편집의 되돌리기 사본이 누적되지 않게 설정 → 일반에 "AI 수정 되돌리기 기록"을 둔다. **기본은 켜짐**이며 저장된 값이 없는 기존 사용자에게도 적용한다. 저장된 꺼짐은 유지한다. 사람의 타자·리본·대화상자 편집은 계속 기록한다. 설정을 바꿔도 기존 편집기 undo 스택은 일괄 삭제하지 않는다.

`AiPanelPrefs.aiEditUndoHistory`를 정규화하고 셸이 `app-settings.json`에 저장하여 모든 뷰에 방송한다. 저장된 불리언을 따르고 값이 없거나 잘못된 경우 기본값을 쓴다. 편집기는 공용 저장소의 `aiEditUndoHistoryEnabled()`로 AI 편집을 기록할지 판정한다. 셸 일반 설정의 문구는 21개 언어를 모두 갖춘다. 홈 AI 계정 옆 톱니바퀴는 일반 설정을, 계정 단추는 AI 설정을 연다.

## 편집기별 적용

다음 표는 설정을 껐을 때 각 편집기가 AI 편집을 처리하는 방식이다.

| 편집기   | AI 출처와 기록 처리                                                                                                                                                                                                                                                                                                                                                                                           |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 엑셀     | 가져온 통합 문서의 `applyChangePlan({ aiEdit: true })`와 MCP 적용은 `createAiUndoScope`가 동기 facade 호출에만 `aiBulkUndoGate.dropAll`을 적용해 처음부터 버린다. 비동기 로드 중의 사람 입력은 기록한다. 사람의 `runUiOps` 기본값은 거짓이다. 빈 통합 문서의 앱 어댑터는 해당 동기 AI 적용이 추가한 개정 사본만 제거한다. 켜짐에서는 통합 문서 전체 AI 기록을 10만 셀 단위로 제한하며 어댑터 사본도 포함한다. |
| 워드     | 공용 `executeTool`이 AI 전용 편집기 facade를 전달한다. facade의 명령·체인·dispatch를 실행하는 동기 구간만 확장이 `addToHistory: false`로 표시한다. 이미지 수신이나 작성 응답을 기다리는 동안 사람이 타자하거나 리본을 눌러도 기록한다. 같은 실행기를 쓰는 MCP도 포함한다. OCR로 연 문서의 별도 되돌리기 사본도 설정을 따른다.                                                                                 |
| 슬라이드 | AI 전용 IPC가 `AsyncLocalStorage`로 요청 출처를 유지한다. AI 요청은 자기 실패 복구 사본만 잠시 갖고 완료 시 제거하며 기존 사람 기록을 예산 때문에 밀어내지 않는다. 실행 배치가 끝날 때 사람 기록을 잘라내지 않는다. MCP 트랜잭션도 해당 호출의 기록만 버린다. QC의 실패 복구 지점은 내부용이며 채팅에 내놓지 않는다.                                                                                          |
| 한글     | AI 호출은 플러그인의 `invokeAi(method, args, recordUndo)`로 들어온다. 앱 플러그인이 고정 studio 버전의 history 실행을 해당 동기 트랜잭션 동안만 감싼다. 원래 트랜잭션의 실패 시 원상 복구는 유지하고 성공한 AI 명령의 사본만 즉시 해제한다. 사람의 메모 패널과 보통 플러그인 호출은 그대로다. 빌드가 의존하는 studio 필드를 확인한다.                                                                         |
| 마크다운 | `runOps`의 `source: 'ai'` 변환만 `addToHistory: false`로 보낸다. 사람의 `uiOp`와 노트 넣기는 그대로다.                                                                                                                                                                                                                                                                                                        |
| HTML     | AI 편집인 `highlight: true`의 CodeMirror 변환에만 `Transaction.addToHistory.of(false)`를 단다. 파일 열기·사람의 타자는 별도 경로다.                                                                                                                                                                                                                                                                           |
| PDF      | AI 도구의 commit마다 `aiEdit`를 전달한다. 이미지 수신·검증 뒤에도 출처가 남고 기다리는 동안 사람의 편집을 가로채지 않는다. AI 편집은 undo 스냅샷을 추가하지 않고 redo만 비운다.                                                                                                                                                                                                                               |
| 마인드맵 | AI가 호출하는 `controller.edit({ aiEdit: true })`는 그리기 라이브러리와 세션의 undo 단계 없이 결과를 적용하고 redo를 비운다. 원본 트리 사본이 사람이 남긴 undo의 기준이다. AI 턴 사본도 만들지 않는다.                                                                                                                                                                                                        |
| EPUB     | AI의 `applyEditGroups({ aiEdit: true })`만 역방향 범위를 보관하지 않는다. 편집 묶음의 원자성과 실패 복구는 유지한다. 타자·찾아 바꾸기는 계속 기록한다. 책 전체 번역은 원래부터 별도 결과 파일이다.                                                                                                                                                                                                            |

마인드맵은 시트당 토픽 2,000개, 원본과 그리기 트리 각각 직렬화 길이 100만 자까지 AI 편집을 기록한다. 누적 기록의 추정 크기는 800만 자, 단계 수는 200개로 제한한다. 한도에 걸리면 편집을 적용하고 그 AI 기록을 생략한다. 요청의 일부만 기록한 경우 채팅에서 전체 요청을 되돌리는 단추를 숨긴다.

AI 인라인 되돌리기 단추와 AI 턴 사본은 꺼짐에서 만들거나 보여 주지 않는다. 켜진 동안 만든 별도 채팅 사본은 끄면 제거하거나 숨긴다. 도구 안내와 실행 지시문은 꺼짐에서 Ctrl+Z를 약속하지 않는다.

앱 안 MCP의 실시간 쓰기는 워드·엑셀·슬라이드에 있다. 다른 편집기의 실시간 MCP는 읽기/저장만 제공하거나 지원하지 않는다. CLI를 통해 닫힌 파일을 직접 고치는 MCP 경로에는 원래 편집기 undo가 없다.

## 한계

- 덱·PDF·빈 통합 문서·마인드맵·한글처럼 과거 상태를 복원하는 편집기에서 옛 사람 편집을 취소하면 그 뒤의 기록하지 않은 AI 변경도 덮어쓸 수 있다. "AI 단계가 쌓이지 않는다"는 설정이며 기존 사람 사본을 재작성하는 기능은 아니다.
- EPUB의 이전 역방향 범위와 AI가 나중에 고친 블록이 겹치면 이전 범위가 맞지 않아 undo가 거절될 수 있다. 이전 사람 기록은 지우지 않으며 범위가 유효한 편집은 계속 되돌린다.
- 한글의 원자적 실패 복구와 슬라이드 요청·QC의 실패 복구에는 일시적인 사본이 필요하다. 이 설정은 성공한 AI 편집의 지속적인 undo 보관을 막는다.
- PDF의 파일 재작성 도구, 별도 번역 결과, 파일 생성은 원래부터 undo 대상이 아니며 이 설정을 켜도 되돌릴 수 있게 되지 않는다.
- 엔진 패키지와 저장 형식은 수정하지 않았다. 빈 엑셀 어댑터와 한글 studio의 내부 history 모양을 쓰는 앱 어댑터는 해당 의존성을 올릴 때 다시 확인한다.

## 검증

기본값·정규화·같음 비교·방송, 홈 톱니바퀴와 일반 설정 저장을 검사한다. 각 편집기의 꺼짐/켜짐, 기존 사람 기록 보존, redo 무효화, MCP 출처를 검사한다. 워드는 AI가 기다리는 동안의 사람 편집, 슬라이드는 비동기 AI 요청 중 사람 편집과 50단계를 넘는 AI 적용, 한글은 실패 후 어댑터 복원도 검사한다. 실제 구독 프로그램은 부르지 않는다.
