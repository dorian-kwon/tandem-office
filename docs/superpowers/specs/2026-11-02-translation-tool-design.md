# 번역툴 설계 (가칭 tandem)

상태: 사용자 승인 완료 (2026-11-02). PDF·스캔·이미지의 번역 결과 형식은 8절의 기본값으로 확정.

## 1. 무엇을, 왜

번역가 한 명이 자기 PC에서 쓰는 번역 전용 데스크톱 앱을 만든다. 이음오피스(IeumOffice, https://github.com/pblsketch/openoffice, Apache-2.0)를 포크해서 그 위에 "번역 프로젝트"라는 층을 얹는다.

번역 한 건에는 번역할 원본 말고도 참고자료, 단어집, 지시문이 따라온다. 지금은 이것들이 흩어져 있어서 AI에게 매번 다시 붙여 넣어야 한다. 이 앱은 프로젝트 단위로 이것들을 묶어 두고, 번역 화면에서 AI에게 자동으로 넘긴다. 원본을 보며 대조하면서 번역할 수 있어야 하고, 스캔본이나 이미지 문서는 OCR로 읽을 수 있어야 한다.

## 2. 목표 / 비목표 / 반(反)목표

**목표**
- 화면 세 개: 프로젝트 목록, 프로젝트 상세, 번역 화면.
- 이음오피스가 여는 모든 문서 형식(Word, Excel, PowerPoint, PDF, HWP, EPUB, 마크다운, HTML 등)을 번역 대상으로 쓴다.
- 프로젝트 정보(프롬프트, 단어집, 참고자료)가 번역 화면의 AI 요청에 자동으로 실린다.
- 원본과 번역본을 나란히 보되, 한쪽을 숨길 수 있다.
- OCR을 사용자가 고른다. 기본은 로그인된 AI다.
- 프로젝트는 폴더와 파일로만 저장된다. 서버, 도커, 계정이 없다.

**비목표**
- 여러 명이 함께 쓰기, 웹 서비스, 계정, 클라우드 동기화.
- 번역 메모리(TM)나 CAT 도구 수준의 문장 단위 대조. 1차에서는 하지 않는다.
- 이음오피스 문서 엔진의 수정. 원본 저장소 규칙상 건드리지 않는다.

**반목표 (기술적으로 돼도 실패인 것)**
- 번역 도중 원본 파일이 바뀌는 것.
- 사용자가 고르지 않은 요금 경로로 AI 요청이 나가는 것. 이음오피스의 "절대 어기지 않는 것" 2번과 같다.
- 번역 화면에서 프로젝트 정보가 AI에게 안 가는데 사용자는 간 줄 아는 것. 무엇이 전달되는지 화면에서 보여야 한다.

## 3. 제약

- 이음오피스 규칙을 따른다. 구독 로그인 정보에 손대지 않고, 구독 프로그램은 도구를 끈 채로 실행하며, 코드 내부 이름(`@genoffice/*`)은 바꾸지 않는다. `LICENSE`, `NOTICE`, 출처 표시를 유지한다.
- 화면 문구는 21개 언어를 모두 채워야 한다. 번역 기능 문구를 한국어와 영어로만 낼지는 8절에서 정한다.
- Windows가 주 배포 대상이고 Mac·Linux는 베타다. 개발 PC는 Mac이다.

## 4. 근거: 이미 있는 것 (원본 저장소 문서에서 확인)

CLAUDE.md, `docs/architecture.md`, `docs/tracking/status.md` 등을 읽고 확인했다. 코드를 실행해 보지는 않았다.

| 필요한 것 | 이미 있는 것 | 비고 |
|---|---|---|
| 모든 문서 형식 편집 | 편집기 9종 | 형식마다 별도 앱 |
| AI 연결 | Claude·ChatGPT 구독 연동 | 공용 AI 창구 `ai:*` |
| 화면 나누기 | 결정 0037, "됨" | 두 칸, 구분선, 초점 따라가는 AI 창. 숨김 토글은 없다 |
| 프로젝트 맥락 | 결정 0088 "프로젝트 폴더" | **구현은 끝났으나 가지 `feat/project-folder`에 있고 사람 확인이 남았다.** main에 합쳐졌는지 확인해야 한다 |
| 번역 | PDF·EPUB 번역 엔진(`pdf-structure`), 결과 보관소 | PDF와 EPUB만. Word 등은 편집기 AI 창으로 번역 |
| 스캔 읽기 | AI 페이지 읽기(`pdf-structure/src/ai-read`) | 스캔 PDF를 AI가 읽는다. PDF 한정 |

## 5. 접근 방식 (사용자가 A를 선택)

- **A. 이음오피스를 포크해 번역 프로젝트 앱을 추가한다. (채택)** 형식 지원과 AI 연결을 그대로 가져온다. 분할 화면을 번역용으로 확장해야 하고, 원본 저장소 규칙을 따라야 한다.
- B. 새 Electron 앱에서 이음오피스 패키지만 가져다 쓴다. 편집기가 패키지가 아니라 앱 단위라서 형식별 편집 기능을 다시 만들어야 한다. 비용이 가장 크다.
- C. 이음오피스는 그대로 두고 프로젝트 관리 도구를 따로 만든다. 가장 빠르지만 번역 화면에서 자동 전달과 분할을 만들 수 없다.

## 6. 설계

### 6.1 저장 구조: 프로젝트 하나 = 폴더 하나

```
<프로젝트 폴더>/
  source/          원본. 읽기 전용으로 취급하고 해시를 기록한다
  references/      참고자료
  glossary/        단어집 파일(csv, xlsx, txt). 읽으면 정규화해 .tandem/glossary.json에 둔다
  output/          번역본(원본의 사본을 열어 고친다)
  .tandem/project.json   이름, 프로젝트 프롬프트, 원문·번역 언어, OCR 방식, 원본 해시
  .ieumoffice/     이음오피스 프로젝트 폴더 기능이 쓰는 지침·기억·대화
```

프로젝트 목록은 앱 설정에 폴더 경로로 기억한다. 폴더를 옮기거나 복사하면 프로젝트가 따라간다.

### 6.2 화면 1: 프로젝트 목록
- **시스템 프롬프트(앱 전체 공통)**: 이 화면에서 입력한다. 어떤 프로젝트를 열어도 모든 AI 요청에 적용된다. 앱 설정에 저장하며 프로젝트 폴더에는 넣지 않는다. 프로젝트 프롬프트가 이를 덮어쓰지 않고 뒤에 덧붙는다(순서: 시스템 → 프로젝트).
- 생성: 이름, 저장 위치, 언어쌍을 입력한다. 폴더와 `.tandem/project.json`을 만든다.
- 삭제: 목록에서만 뺄지, 폴더까지 지울지 묻는다. 폴더 삭제는 되돌릴 수 없다고 확인받는다.
- 목록: 이름, 언어쌍, 최근 연 날짜.

### 6.3 화면 2: 프로젝트 상세
- 번역할 문서, 참고자료, 단어집을 각각 올리고 각각 지울 수 있다. 올린 파일은 폴더로 복사한다. 지우면 폴더의 사본도 지운다. 원본 파일은 건드리지 않는다.
- 프로젝트 프롬프트를 입력한다. 이 프로젝트에만 적용된다.
- OCR 방식을 고른다(6.5).
- 번역할 문서를 고르면 번역 화면으로 열린다.

### 6.4 화면 3: 번역 화면
- 원본을 읽기 전용 탭으로 왼쪽에, `output/`의 사본을 편집 탭으로 오른쪽에 둔다. 이음오피스의 화면 나누기(0037)를 쓴다.
- 두 칸 각각을 접었다 펼 수 있다. 숨겨도 상태(위치, 스크롤)는 유지한다. 이 토글은 새로 만든다.
- AI 창에 프로젝트 맥락을 자동으로 싣는다. 시스템 프롬프트, 프로젝트 프롬프트, 단어집, 참고자료. 실린 항목은 AI 창에서 칩이나 목록으로 보여 준다.
- 단어집: 작으면 전체를 싣는다. 크면 요청한 문단에 나오는 용어만 골라서 싣는다.
- 참고자료: 파일 이름 목록과 검색 도구로 AI가 필요할 때 읽게 한다. 전체를 매번 싣지 않는다.
- 번역본은 원본 사본을 편집기에서 고치는 방식이다. 형식 서식이 그대로 유지된다.

### 6.5 OCR
- 선택지(프로젝트 설정, 번역 화면에서도 바꿀 수 있음):
  1. **AI 읽기(기본)**: 로그인된 Claude나 ChatGPT가 페이지 이미지를 읽는다. PDF는 기존 AI 페이지 읽기를 쓴다. 어느 AI로 읽을지는 이음오피스의 제공자 선택을 따르되 OCR용으로 따로 고를 수 있다.
  2. **끔**: 문서에 이미 들어 있는 글자만 쓴다.
- 로컬 OCR은 만들지 않는다(사용자 결정, 2026-11-02). 나중에 필요하면 선택지에 추가하는 별도 작업이다.
- AI 읽기는 페이지 이미지를 제공자에게 보낸다. 시작 전에 요금과 전송 사실을 알린다. 기존 AI 페이지 읽기가 이미 하는 확인 창을 따른다.
- 대상: 스캔 PDF, 단독 이미지 파일(png, jpg). 문서 안에 박힌 이미지의 OCR은 1차 범위 밖이다.

### 6.6 확장 지점
- 프로젝트 목록과 상세는 껍데기 앱(`apps/shell`)에 새 홈 화면으로 더한다.
- 프로젝트 맥락의 주입은 프로젝트 폴더 기능(0088)이 지시문에 붙이는 글에 번역 항목을 더하는 방식으로 한다. 번역 프로젝트는 0088의 프로젝트이기도 하다.
- 포크한 저장소에 번역 전용 코드는 새 디렉터리(`apps/shell`의 번역 모듈과 `packages/translate-project` 등)에 둔다. 문서 엔진 패키지는 수정하지 않는다.

## 7. 채택한 기본값 (제 판단, 사용자가 확인 필요)

- 원본은 `source/`에 복사하고 해시를 기록한다. 번역은 사본 `output/`에서 한다.
- 단어집은 csv, xlsx, txt 세 형식을 읽는다. 열은 `원어, 번역어, 비고` 순서로 본다.
- 프로젝트는 표준 폴더 구조를 쓰되 `.tandem/project.json`이 진실의 원천이다.
- 제품 이름은 가칭 tandem이다. 이음오피스의 이름과 브랜드를 그대로 쓰지 않는다. 최종 이름은 나중에 정한다.

## 7-1. 검토 후 반영한 것

**저장소에서 확인한 사실**
- 프로젝트 폴더 기능의 코드 디렉터리(`apps/shell/src/main/projects`)가 main에 있다. 합쳐진 것으로 보이나 사람 확인이 남았다는 상태 기록은 그대로다. 포크 직후 빌드해서 동작을 확인하는 것이 1단계다.
- 분할 화면(0037)은 서로 다른 문서를 두 칸에 놓을 수 있다(예: 원본 PDF와 Word 사본). 읽기 전용 칸은 없다. 새로 만든다.

**제 판단으로 정한 것 (빌더가 바꿔도 되지만 기본값은 이렇다)**
- 원본 보호: 앱이 `source/`의 파일을 열 때 읽기 전용 모드로만 연다. 열 때마다 해시를 비교해서 달라졌으면 알리고 사용자가 고르게 한다. OS 파일 권한은 건드리지 않는다.
- 삭제: 상세 화면에서 번역할 문서를 지워도 `output/`의 번역본은 지우지 않는다. 번역본은 따로 지우며 확인을 받는다. 번역가의 작업물을 실수로 잃지 않게 하기 위해서다.
- 참고자료를 AI가 읽는 방식: 구독 프로그램은 도구를 끈 채 실행된다는 규칙이 있다. 그래서 프로젝트 폴더 기능이 이미 쓰는 앱 쪽 읽기 도구 방식을 따른다. 이 방식이 번역 요청에 안 통하면 요청한 문단과 관련된 발췌를 지시문에 실어 주는 방식으로 대체한다.
- 단어집: UTF-8과 CP949를 자동 판별한다. 첫 줄이 제목이면 건너뛴다. xlsx는 첫 시트만 읽는다. 항목이 200개 이하면 전체를 싣고, 넘으면 해당 문단에 나온 용어만 싣는다. 200은 설정에서 바꿀 수 있다.

## 8. 아직 정하지 않은 것

**사용자 결정 완료 (2026-11-02)**
- 시스템 프롬프트는 모든 프로젝트에 공통, 프로젝트 프롬프트는 해당 프로젝트에만 적용.
- 로컬 OCR은 넣지 않고 AI 방식만 쓴다.

**사용자 확인이 남은 것**
- 직접 고칠 수 없는 원본(PDF, 스캔, 이미지)의 번역 결과 형식. 아래 기본값으로 진행하며 승인 때 함께 확인한다. 일반 PDF는 기존 번역 엔진의 번역 PDF(선택 시 대역본), 스캔 PDF와 이미지는 OCR 결과를 Word 문서로 만들어 그 문서에서 번역한다.

**빌더에게 맡긴다**
- 분할 화면의 스크롤 연동 방식, 문단 대응.
- 단어집 용어 매칭 알고리즘(형태소, 대소문자 등).
- 화면 문구를 21개 언어로 낼 시점.
- 원본 저장소의 `feat/project-folder`가 main에 합쳐졌는지 확인하고, 아니면 어떻게 가져올지 정하는 것.

## 9. 위험

- 0088(프로젝트 폴더)이 main에 없으면 번역 맥락 주입의 기반을 먼저 가져와야 한다.
- 편집기마다 AI 도구가 달라서 형식별로 번역 품질과 서식 보존이 다를 수 있다. 형식별 확인이 필요하다.
- 원본 저장소가 활발히 바뀐다. 포크 후 원본의 개선을 받아오는 절차(`docs/operations.md`)를 따라야 한다.
