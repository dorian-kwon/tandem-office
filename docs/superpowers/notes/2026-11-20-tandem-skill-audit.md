# Tandem 스킬 검증 기록

2026-11-20. v0.15.8의 공통 조상부터 포크가 추가·수정한 스킬을 조사했다. 개발 PC의 개인 스킬 모음은 범위에서 제외했다. 아래 결함은 기존 버전에서 발견한 것으로 번역 위키 스킬 추가와 독립적이다.

## 구현과 지침 사이의 차이

- 시트 번역에서 `translation: true`를 넣어도 값 쓰기와 서식을 섞은 배치는 일반 Undo로 돌아갈 수 있다. 슬라이드도 텍스트·노트·표 셀 외의 서식 작업이 섞이면 배치 단위로 돌아간다. 개별 실행취소를 안내할 때 배치 조건까지 일치시켜야 한다. `apps/sheets/src/renderer/ai/prompts/base.md:46`, `apps/sheets/src/renderer/ai-undo-scope.ts:84`, `apps/slides/src/main/slides-main.ts:1420`.
- 프로젝트 공통 지침은 OCR 배치를 물으라고 하고 PDF·HWP·HWPX 결과 지침은 Word 파일 작성 여부만 확인하도록 한다. 한글의 ‘모든 그림’ 안내도 실제 PNG/JPEG 열거 범위보다 넓다. `packages/translate-project/src/compose.ts:169`, `packages/ui/src/ocr-chat-skill.ts:9`, `apps/shell/tests/translate-ocr-extracted.test.ts:98`.
- 개발용 릴리스 스킬에는 원본 프로젝트 사이트 게시 절차, 현재 업데이트 화면과 다른 다중 버전 머리글 검사, 현재 환경과 다른 한국어 윤문 스킬 이름이 남아 있다. 현재 Tandem 저장소·피드에 맞춰야 한다. `.claude/skills/release-ieumoffice/SKILL.md:20,28,69,84`, `docs/releasing.ko.md:61,181,291`.

## 정상 동작과 검증 범위

- 기존 내장 목록 7개를 실제 앱 로더에서 확인했다. 외부 배포 스킬 5개 중 4개는 고정한 원문과 바이트 일치, find-skills는 원문에 앱 설치 미리보기 안내가 추가됐다. 행정보고서 2개는 이음에서 계승했다. CLI 스킬의 상위 명령 21개가 실제 도움말에 있고 기준 커밋 대비 버전 검사도 통과했다.
- 포크에서 추가한 공통 OCR과 시트 그림 OCR은 실행 시 등록하는 도구다. Word의 프로젝트 지침에 나온 `read_runs`, `translate_blocks`, `add_bilingual`도 실제 스키마에 있다. OCR·번역 프로젝트 집중 시험 32파일 567건, 9개 편집기 집중 시험 96건이 통과했다. 기존 시험이 다루지 않은 사례는 위에 별도 기록했다.
- 실제 고객 자료나 외부 OCR·번역 서비스 호출 없이 synthetic fixture, 실제 편집기 도구, 모의 응답을 사용했다. 이 검증에서 기존 결함은 수정하지 않았다.

## 수정 후 재검증

Tandem에서 추가한 완성본 번역 위키와 OCR·번역·병기·서식 유지 경로를 합성 자료와 로컬 모의 응답으로 검증했다.

| 대상               | 확인한 동작                                                                                                                                                                                                                                                                                                                                                           |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 완성본 번역 위키   | 내장 로더에서 스킬을 선택하고 최종 산출물·출처·분류 규칙이 요청에 들어가는지 확인했다. 자동 색인과 Obsidian 연결은 별도 구현 단계다.                                                                                                                                                                                                                                  |
| 번역 · 병기 · 서식 | Word에서 중복 원문, 같은 문자권, 중첩 표, 수동 수정 후 이어 번역을 검증했다. Markdown에서 선택 경계를 지키고, 시트와 슬라이드는 번역 단위 Undo와 충돌하는 서식 요청을 쓰기 전에 거부한다. PDF·EPUB은 배치의 번역 대상과 원문 개요·확정된 이전 번역을 구분한다.                                                                                                        |
| OCR · 표 안의 표   | 서로 다른 그림이 들어 있는 바깥 표와 안쪽 표를 사용했다. DOCX에서 안쪽 그림만 골라 안쪽 셀, 그림 뒤, 그림 위에 배치한 뒤 다시 열어 확인했다. HWP와 HWPX에서는 문서 엔진이 반환한 안쪽 그림의 셀 경로 깊이(2)를 확인하고, 그 그림만 선택해 로컬 OCR 수신 바이트의 SHA-256과 새 DOCX 출력을 대조했다. 8일 뒤를 가정해 임시 자료를 정리한 뒤에도 결과와 원본이 유지됐다. |
| 긴 시트 그림 OCR   | 그림 하나의 미리보기와 전체 채팅 미리보기 상한을 모두 넘기는 결과에서, 도구의 다음 위치를 따라 모든 원문을 복원했다. 다른 통합문서의 결과 식별자는 거절한다.                                                                                                                                                                                                          |

중첩 한글 시험 파일 `apps/shell/tests/fixtures/ocr-nested-tables.{hwp,hwpx}`는 기존 한컴 작성 시험 파일 `apps/hwp/tests/fixtures/nested-form.hwp`의 바깥 셀과 그 안의 시험 표 셀에 서로 다른 1픽셀 PNG를 넣은 사본이다. 예상 위치와 바이트를 고정해 OCR 제공자의 인식 결과와 독립적으로 선택·전달 경로를 검사한다.

대용량 회귀에서는 HWP·HWPX 500쪽 각각에서 문단 500개 적용 → Undo 500회 → Redo 500회 후 모든 쪽의 내용과 원본 파일 해시를 대조했다. 57,455,410바이트의 500쪽 PDF는 떨어져 있는 제목 60개를 제자리에서 수정한 뒤 실행취소·다시실행했다. 전용 EPUB 번역은 1,607개 단위를 17개 묶음으로 처리하고 디스크에 저장한 상태에서 이어가는 경로를 검증했다.
