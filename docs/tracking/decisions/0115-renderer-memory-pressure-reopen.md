# 0115 — PC 메모리 압박을 보고 문서 다시 열기를 제안한다

- 날짜: 2026-11-18
- 상태: 적용

## 맥락

렌더러 하나가 1.5GB를 넘었다는 이유만으로 경고하면 메모리가 넉넉한 PC에서도 경고한다. 오래 열린 문서의 메모리를 돌려받으려면 문서를 다시 열 수 있어야 하지만 저장하지 않은 내용과 진행 중 AI 작업을 지켜야 한다.

## 결정

메모리는 `privateBytes`가 있으면 그것을, 없으면 `workingSetSize`를 쓴다. 아래 중 하나이면 기존의 연속 표본·재알림 간격에 따라 경고한다.

- 렌더러가 1536MB를 넘고 PC 가용 메모리가 `max(1536MB, 전체의 10%)`보다 적다.
- 렌더러가 PC 전체 메모리의 50%를 넘는다.

PC 메모리는 미리 띄운 엑셀 화면과 같은 `readMemory`로 읽는다. CPU 규칙은 그대로다.

경고에는 ‘계속 기다리기’(기본·Esc), ‘문서 다시 열기’, ‘문서 닫기’가 있다. 파일 경로가 없으면 다시 열기는 없다. 다시 열기는 보통 닫기와 같은 저장 확인을 통과한 뒤 렌더러를 새로 만들며 탭의 번호·자리·분할을 유지한다. 저장 취소·실패이면 그대로 둔다.

AI가 일하는 동안에는 이유를 설명하고 ‘AI가 끝나면 다시 열기’를 제안한다. 구독 스트림의 끝이 아닌 편집기 전체 작업, 문서 적용, 번역·읽기 작업, 결과 쓰기, 저장과 MCP 작업의 끝까지 기다린다. 저장 확인 전후에 다시 확인하고, 문서가 닫히면 예약을 버린다. AI가 같은 문서의 파일 이름을 바꾸었으면 현재 경로로 다시 연다. 실행 상태를 읽을 수 없으면 다시 열지 않는다.

문제 보고서에는 최근 유효한 감시 JSON 기록 최대 3개를 담는다. 각 파일과 읽을 후보 수를 제한하고, 숫자 자원 측정값과 허용된 편집기 종류만 추린다. 문서 제목·경로·URL·내용·임의 문자열과 CPU 프로필은 보고서에 넣지 않는다. 아무것도 전송하지 않는다.

## 확인

임계값과 CPU 유지, 버튼 번호와 기본/취소, AI 적용 대기, 닫힌 문서, 저장 취소, 같은 탭 자리, 진단 파일 상한과 민감한 값 제거를 가짜 편집기와 파일로 확인한다. 실제 구독은 부르지 않는다.
