# 0109 문제 보고서는 앱이 모아 두고, 사람이 파일로 저장해 직접 보낸다

## 맥락

크래시 기록(`crash-log.jsonl`)은 PC에만 남고 밖으로 나가지 않으며, 시각·종류·이유 낱말·종료 코드·편집기·메모리 숫자만 담았다. 그래서 두 가지가 안 됐다. 하나는 "화면이 사라진다"(React #185)처럼 프로세스는 살아 있고 화면만 깨지는 오류가 기록에 아예 남지 않아 원인을 찾을 스택이 없었다. 다른 하나는 사용자가 문제를 알리려 해도 어떤 파일을 어디서 찾아 보내는지 몰랐다. 저장소 주인은 "크래시 로그를 더 자세히 주고, 메뉴에서 리포트를 누르면 파일로 저장하게 해 달라"고 했다.

이 앱에는 서버·계정·사용 통계가 없고 사용 통계 전송은 없앤 기능이다(`tests/removed-features.test.ts`). 크래시 덤프는 문서 내용이 담길 수 있어 켜지 않는다. 자동으로 보내는 길은 이 결정에서도 열지 않는다.

## 결정

**기록을 더 자세히 하되 식별자 꼴로만 하고, 모아서 파일로 저장하는 일은 사람이 한다.**

- **크래시 줄의 새 칸:** 앱이 켜져 있던 초(`uptimeS`), 편집기별 열린 탭 수(`tabs`), 이번 실행의 마지막 동작 24개(`trail`). 동작은 정해진 단어(`tab-open:docs`, `ai-start`, `update-check`, `quicklook-hook-on`)만이고 소문자·공백 없는 단어 꼴이 아니면 버린다. 제목·경로·파일 이름은 들어갈 수 없다.
- **화면 오류 줄(`renderer-error`):** 모든 화면에 작은 스크립트를 심어 미처리 오류와 거절된 약속을 콘솔의 표식 줄로 보고하게 하고, 메인이 그 줄만 읽는다(`startRendererErrorWatch`). 남기는 것은 오류의 종류 이름, React 오류 번호, 우리 번들 맨 위 6개 틀의 `함수@파일.js:줄:칸`뿐이다. 오류 메시지는 문서 글을 인용할 수 있어 버린다. 같은 오류는 1분에 한 번, 실행당 20개까지만 쓴다(렌더링 되풀이가 기록을 채우지 않게). 창 없는 내보내기에서는 켜지 않는다.
- **도움말 → "문제 보고서 저장…":** 모든 탭 종류의 도움말 메뉴에 들어간다(`withHelpItems`). 먼저 파일에 무엇이 드는지를 보여 주고, 사람이 고른 곳에만 텍스트 파일을 쓰며(`saveCrashReport`), 쓴 뒤 폴더에서 보기를 권한다. 앱은 아무것도 보내거나 복사하지 않는다. 파일에는 앱·Electron·Chromium 버전, 운영체제와 화면 언어, 실행 시간, 열린 탭 수, 이번 실행의 동작, 크래시 기록 끝 40줄, 저장 실패 기록 끝 20줄, 업데이트 기록 끝 80줄이 든다. 업데이트 기록은 설치 파일과 앱의 경로를 인용하므로 모든 기록에서 사용자 폴더 이름을 `<user>`로 가린다(`scrubUserPaths`).
- **문구는 21개 언어로 둔다**(`crash-report-save.ts`의 `CRASH_REPORT_STRINGS`, 시험이 모든 언어와 키를 확인한다).

## 버린 대안

- **자동 전송(Sentry 같은 서비스):** 서버를 쓰게 되고 `PRIVACY.md`와 `docs/security.md`의 약속을 바꿔야 한다. 크래시 덤프를 보내면 문서 내용이 새고, 요약만 보내는 길도 사용자가 켠 경우로 한정해야 한다. 신고가 모자라는 때가 오면 따로 결정한다.
- **오류 메시지를 함께 기록:** 메시지는 문서 글이나 경로를 인용한다(ProseMirror 오류가 그렇다). 오류 종류와 React 번호와 위치로 줄인다.
- **설정 → 정보에 단추도 두기:** 이번에는 메뉴 하나로 한정했다. 필요하면 의견 보내기 옆에 같은 함수를 부르는 단추를 더한다.

## 결과

- 새 모듈: `activity-trail.ts`(동작 기록과 탭 변화), `renderer-errors.ts`(화면 스크립트, 표식 줄 해석, 중복 억제), `crash-report.ts`(보고서 본문), `crash-report-save.ts`(대화 상자 흐름과 문구). `crash-log.ts`의 칸이 늘었다.
- 시험: `crash-log-detail`, `activity-trail`, `renderer-errors`, `crash-watch-detail`, `crash-report`, `crash-report-save`, `crash-report-wiring`.
- 한계: 번들은 줄여 쓴 것이라 `frames`의 함수 이름은 `Ke`처럼 줄어 있다. 읽으려면 같은 빌드의 소스맵이 있어야 하는데 릴리스는 소스맵을 남기지 않는다. 동작 기록은 탭 열고 닫기, AI 시작·끝(2초 간격으로 확인), 업데이트 확인·받기·설치, 탐색기 미리보기 도우미 켜고 끄기, 앱 시작·종료만이다. 저장·번역·OCR은 아직 넣지 않았다.
