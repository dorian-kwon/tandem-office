# 0105 그림 OCR을 PDF·한글(HWP·HWPX)로 넓히고, 결과는 새 Word 문서로 쓴다

## 맥락

그림 속 글 OCR은 docx와 xlsx에서만 됐다. 한글(HWP·HWPX)은 번역 프로젝트의 원본으로 넣을 수는 있어도 "편집기에서 번역하는 형식"이라며 OCR을 거절했고, 대화창의 `document_ocr`는 docx·xlsx만 받았으며, PDF는 번역 창에서 스캔 쪽 읽기만 됐다. 사용자는 PDF, HWP, HWPX, DOC도 되기를 원했다(계획 `docs/plans/ocr-more-formats.md`).

## 결정

- **읽은 글은 새 Word 문서로 쓴다.** `output/<이름> (OCR).docx`다. 스캔 PDF가 이미 하는 방식과 같다. 원본 HWP·HWPX·PDF는 건드리지 않는다. 박스나 "그림 뒤 문단"처럼 원본 안으로 되넣는 일은 하지 않는다. 결정 0104의 박스 배치는 docx 그림에만 남는다.
- **HWPX와 HWP는 그림을 꺼내 읽는다.** HWPX는 압축 파일 안 `Contents/content.hpf`의 목록과 `Contents/section*.xml`·`Contents/header.xml`이 `binaryItemIDRef`로 가리키는 `BinData/`의 PNG·JPEG를 문서 순서로 나열한다(같은 그림은 한 번, 가리키는 곳이 없는 그림은 뺀다). HWP는 복합 파일의 `/BinData/BIN*.png|jpg` 스트림을 이름 순으로 나열하고, 읽을 때 그림 머리글자로 판별해 압축(deflate) 여부와 상관없이 푼다. 암호가 걸렸거나 배포용인 HWP는 읽지 않고 이유를 알린다(`openHwp`가 이미 거른다).
- **`OcrPrepared.kind`에 `'extracted'`를 더한다.** 문서 안에서 꺼낸 그림이고, 박스·배치 단계가 없고, 결과는 새 docx다. 화면은 `'embedded'`처럼 그림 목록과 썸네일을 보이되 배치 화면은 건너뛴다. PDF(`'pdf'`)도 결과가 새 docx이므로 같은 길이다.
- **대화창의 `document_ocr`도 PDF·HWP·HWPX를 받는다.** `propose`는 이 형식에서 배치를 추천하지 않고 `result: "new-docx"`와 검토할 글만 낸다. 모델이 지어낸 `placement`는 무시한다. `apply`는 배치 없이 `write`를 부른다. AI에게는 `ocrPlacement` 질문 카드를 띄우지 말고 새 Word 문서에 쓴다는 것만 확인하라고 안내한다. PDF 쪽은 쪽 그림이라 쪽 읽기 요청을, 한글 그림은 그림 읽기 요청을 쓴다.
- **옛 `.doc`는 읽지 않는다.** 앱에 읽는 엔진도 변환기도 없다. 번역 프로젝트의 원본으로 받지 않는 지금 동작을 그대로 두고, 대화창 OCR이 `.doc`를 만나면 "Word에서 `.docx`로 저장해 그 파일을 넣으라"고 알린다. 형식을 몰래 바꾸지 않는다.
- **지키는 것.** 그림 하나에 AI 호출 하나, 확인 화면의 요금 문구, 사람이 고른 쪽·그림만 읽는 규칙, 한 번에 읽는 개수 한도는 그대로다. 문서 엔진 패키지는 고치지 않았다. 그림이 하나도 없는 문서는 "읽을 그림이 없다"(`OCR_FAILED`)로 끝난다.

## 버린 대안

- **한글 원본 안에 읽은 글을 되넣기**: HWP·HWPX 쓰기는 편집 엔진(rhwp)과 문서 호환의 약속(0079)에 걸리고, 그림 위치를 HWP 바이너리에서 안정적으로 알 수 없다.
- **`.doc`를 앱 안에서 변환해 읽기**: 믿을 만한 변환기가 없다. 형식을 바꾸는 일은 사람이 한다.
- **한글 그림을 위한 새 읽기 화면**: 목록·미리보기·확인 화면은 docx의 것을 그대로 쓰고 배치 단계만 건너뛰는 편이 작고 안전하다.

## 결과

- 번역 프로젝트의 HWP·HWPX 원본에도 "그림 속 글 읽기"가 열리고, PDF와 한글 그림의 읽은 글은 원본 옆 `output/`에 새 docx로 나온다. 대화창에서도 같은 길로 이야기하며 읽는다.
- HWP 바이너리의 그림은 쪽·문단 위치를 알려 주지 않고 문서 안 순서와 파일 이름으로만 나열한다. BMP·GIF 등 AI가 읽지 못하는 형식의 그림은 목록에서 빠진다(`docs/tracking/findings.md`).
- 실제 한글 문서와 실제 구독 AI로 읽어 본 확인은 아직 못 했다(합성 파일 단위 시험까지).
