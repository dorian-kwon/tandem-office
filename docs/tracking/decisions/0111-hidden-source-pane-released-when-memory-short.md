# 0111 번역 화면에서 숨긴 원본 칸은 메모리가 모자라면 내려 두고, 보일 때 다시 연다

## 맥락

번역 화면은 원본(읽기 전용 사본)과 결과를 항상 나란히 연다. 칸을 숨겨도 그 칸의 문서는 자기 렌더러에 통째로 남아 메모리를 쓴다. 2026-11-18에 macOS에서 잰 값으로 3천 행 통합 문서 하나가 엑셀 화면 656MB와 메인 +200MB였다. 번역은 같은 문서를 두 칸에 여니 그 두 배에 가깝다(두 칸을 같이 잰 것은 아니다). 원본 칸은 읽기 전용이라 편집이 없고, 결정 0110(미리 띄운 엑셀 화면)의 램 읽기와 기준을 그대로 쓸 수 있다.

## 결정

**숨긴 읽기 전용 칸은 쓸 수 있는 메모리가 넉넉하지 않으면 렌더러를 내려 두고, 칸을 보이면 파일에서 다시 읽는다.**

- **언제 내리나:** 번역 분할에서 칸이 숨겨져 있고, 그 칸이 읽기 전용이며, 30초마다 본 PC의 쓸 수 있는 메모리가 만들기 기준(3GB 이상이고 전체의 20% 이상) 아래일 때(`hiddenPaneVerdict`). 보이는 칸과 편집하는 결과 칸은 내리지 않는다. 메모리가 넉넉하면 그대로 둔다.
- **내린 뒤:** 탭은 탭 줄에 그대로 있고(읽기 전용, 같은 묶음), 분할도 숨긴 칸 그대로 남는다. 탭은 "불러오지 않은 탭"이 되어 `plainTabOpener`(파일을 디스크 그대로 연다)가 열쇠를 쥔다. 화면은 닫힌 탭과 같은 방식으로 내린다(워드는 `teardownDocsRenderer`와 `releaseClosedRenderer`, 나머지는 `webContents.close()`). `layout()`은 숨긴 채 내려진 칸의 화면 없음을 낡은 참조로 보고 분할을 풀지 않는다(`paneHasPlace`).
- **보일 때:** 칸 숨기기 단추가 그 칸을 보이게 하는 길(그 칸을 보이거나 반대쪽 칸을 숨겨 이 칸이 보이게 되는 경우)과 탭 줄에서 탭을 고르는 길이 모두 먼저 파일을 다시 읽고(`loadTab`), 새 화면에 읽기 전용 보호를 다시 건다. 읽기에 실패하면 칸은 숨긴 채로 두고 다시 시도할 수 있다. 칸 역할은 새 화면이 시작할 때 스스로 묻는다(`app:get-split-role`).
- **한 방향:** 메모리가 다시 넉넉해져도 저절로 되살리지 않는다. 사람이 보일 때만 읽는다.
- **분할이 숨긴 채 시작할 때**(기억해 둔 배치 복원)도 같은 감시를 건다.

## 알려야 할 것(대가)

다시 보일 때 문서를 다시 여는 몇 초가 걸리고, 그 칸의 스크롤 위치와 선택은 처음으로 돌아간다.

## 버린 대안

- **보이는 칸까지 내리기:** 사람이 보는 칸이 비게 된다.
- **메모리가 회복되면 자동으로 되살리기:** 칸을 숨긴 사람이 모르게 문서가 다시 열리고, 기준 근처에서 내렸다 올렸다를 되풀이할 수 있다.
- **칸을 숨기는 즉시 내리기:** 숨겼다 곧 다시 보는 흔한 사용에서 매번 다시 읽는 비용이 든다. 메모리가 넉넉하면 내릴 이유도 없다.

## 결과

- `tab-manager.ts`(`releaseReadOnlyView`, `watchHiddenSourcePane`, `paneHasPlace`, `loadTab`의 읽기 전용 보호), `spare-view-policy.ts`(`hiddenPaneVerdict`, `HIDDEN_PANE_RECHECK_MS`).
- 시험: `tests/translation-split.test.ts`의 "letting go of a hidden source pane when memory is short"(넉넉할 때 두기, 모자랄 때 내리기와 분할 유지, 보이는 칸과 결과 칸은 두기, 나중에 모자라질 때, 감시 전에 다시 보임, 다시 읽기, 반대쪽 칸을 숨겨 보이게 될 때, 탭 줄에서 고르기, 읽기 실패, 처음부터 숨김, 묶음과 함께 닫기), `tests/spare-view-policy.test.ts`.
- 실제 앱 확인(macOS, 24GB 중 쓸 수 있는 1.4GB): 번역 분할의 화면 프로세스가 3개(홈, 원본, 결과)에서 원본 칸을 숨기고 40초 뒤 2개로 줄었고, 원본 탭은 읽기 전용으로 탭 줄에 남았다. 칸을 보이자 3개로 돌아오고 원본 칸에 문서 글이 다시 나타났다. 한계: Windows에서는 확인하지 못했고, 내려진 뒤 메모리가 얼마나 줄었는지는 프로세스 수로만 확인했다.
