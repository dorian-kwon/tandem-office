# OCR을 PDF·HWPX·HWP로 넓히기

상태: 구현됨(합성 파일 단위 시험까지, 실제 한글 문서와 구독 AI 확인 남음, 결정 0105). 대상: 번역 프로젝트 OCR(`apps/shell`)과 편집기 AI 대화창의 `document_ocr`.

## 의도

그림 속 글 OCR은 docx와 xlsx에서만 되고, 한글(HWP·HWPX)은 원본으로 넣을 수는 있어도 OCR은 "편집기에서 번역하는 형식"이라며 거절했다. 대화창의 `document_ocr`는 docx·xlsx만 받았고 PDF는 번역 창에서 스캔 쪽 읽기만 됐다. 사용자는 PDF, HWP, HWPX, DOC도 되기를 원한다.

## 결정(사용자가 정함)

- 읽은 결과는 **새 Word 문서**(`output/<이름> (OCR).docx`)로 쓴다. 스캔 PDF가 지금 하는 방식과 같다. 원본 HWP·HWPX·PDF는 건드리지 않는다. 박스나 "그림 뒤 문단"처럼 원본 안에 되넣는 것은 하지 않는다.
- 옛 `.doc`는 앱이 읽는 엔진이 없고 변환기도 없다. 번역 프로젝트의 원본으로 받지 않는 지금 동작을 유지하고, 대화창 OCR이 만나면 docx로 저장하라는 안내를 낸다.

## 범위

| 형식 | 어떻게 읽나                                                                                                                    | 어디서                         |
| ---- | ------------------------------------------------------------------------------------------------------------------------------ | ------------------------------ |
| PDF  | 쪽을 그림으로 그려 읽는다(지금 있는 길)                                                                                        | 번역 창(이미 됨), 대화창(새로) |
| HWPX | 압축 파일 안 `BinData/`의 그림. `Contents/section*.xml`과 `Contents/header.xml`(바탕·채우기)이 `binaryItemIDRef`로 가리키는 것 | 번역 창, 대화창                |
| HWP  | 복합 파일의 `/BinData/` 스트림. 문서 설정에 따라 deflate 압축이거나 아니거나 하므로 그림 머리글자(PNG·JPEG)로 판별한다         | 번역 창, 대화창                |
| DOC  | 읽지 않는다. docx로 저장하라는 안내                                                                                            | 대화창                         |

## 만드는 것

- `listEmbeddedImages`가 HWPX를, 같은 파일의 `listHwpImages`가 HWP를 나열한다. 같은 `EmbeddedImage` 모양이고 HWP는 압축을 푸는 `read`를 갖는다.
- `OcrPrepared.kind`에 `'extracted'`를 더한다. 문서 안에서 꺼낸 그림이고, 박스·배치 단계가 없고, 결과는 새 docx다. 화면은 `'embedded'`처럼 그림 목록과 썸네일을 보이되 배치 화면은 건너뛴다.
- 대화창 OCR 서비스는 `inspect`에서 PDF·HWP·HWPX를 받고, 배치 제안·적용 단계는 이 종류에서 "새 Word 문서" 하나로 줄인다.

## 지키는 것

- 비용·전송: 그림 하나에 AI 호출 하나, 확인 화면의 문구와 사람이 고른 쪽만 읽는 규칙은 그대로다. 문서 엔진 패키지는 고치지 않는다.
- 암호가 걸렸거나 배포용인 HWP는 읽지 않고 이유를 알린다(`openHwp`가 이미 거른다).
- 그림이 하나도 없는 문서는 "읽을 그림이 없다"로 끝낸다.

## 알려진 한계(미리)

- HWP 바이너리의 그림은 위치(몇 쪽, 어느 문단)를 알려 주지 않고 문서 안 순서로만 나열한다.
- HWP·HWPX·PDF 안에 읽은 글을 되넣거나 박스를 놓지 않는다.
- 옛 `.doc`는 직접 읽지 않는다.
